# Ficha A4 — Una versión vieja de la API sigue viva (`/api/v1` zombie)

> App vulnerable a propósito — solo laboratorio (127.0.0.1). Datos 100 % ficticios.
> Categoría OWASP: **API9:2023 Improper Inventory Management**. Flag: `VULN_A4=on|off`.
> Módulo: `api/src/vulns/a4.ts`. (El ID «A4» es la etiqueta del lab, no la categoría.)

## Qué es
La tienda sirve su API en `/api/v2`, con autenticación y privacidad por objeto. Con
`VULN_A4=on` quedó montada, olvidada, una versión anterior: `/api/v1`. Expone
`GET /api/v1/users`, un endpoint legado de **antes de que existiera la auth**, que devuelve la
lista completa de usuarios con su PII (correo, RUT, rol) **sin pedir sesión**. El control de
acceso que sí tiene v2 nunca se portó a v1, y nadie decomisionó v1.

## Por qué ocurre: inventario de la API
No es un fallo de código, es un fallo de **gestión del inventario**. Cada versión, cada ruta y
cada entorno publicado es superficie de ataque que alguien debe conocer y mantener. Una
versión vieja que sigue viva:
- **Reintroduce fallos ya corregidos.** La auth se añadió en v2; v1 se quedó sin ella. El
  arreglo existe, pero hay una puerta por la que no se aplica.
- **Nadie la vigila.** No está en la documentación actual, no sale en los tests del equipo, no
  tiene dueño. Los monitores miran v2.
- **«Dejar de usar» no es «retirar».** Que el front ya no llame a v1 no la apaga: sigue
  respondiendo a quien la pida directo.

```
// on (defecto): se monta el router legado sin auth
GET /api/v1/users  → 200, lista de usuarios con PII
```

## La corrección (`VULN_A4=off`)
`/api/v1` no se monta en absoluto. Cualquier ruta bajo ese prefijo cae en el notFound handler
y responde **404**. El inventario de la API es **una sola versión soportada**. Retirar, no solo
dejar de enlazar.

```
// off: v1 no existe
GET /api/v1/users  → 404 NOT_FOUND
```

## Cómo practicarlo (herramienta de práctica)
Con la API del lab corriendo en local y `VULN_A4=on`:

1. Sin ninguna cabecera `Authorization`, pide `GET /api/v1/users`.
2. En `on` responde **200** con la lista de usuarios y su PII (incluye el admin del seed,
   `admin@trastomaldito.test`). Esa es la fuga: datos privados sin autenticación.
3. Compara con v2: `GET /api/v2/admin/relics` sin token responde 401. La auth existe… pero no
   en v1.
4. En **Burp Suite**, con *Intruder* y una lista de rutas (`/api/v1/...`, `/api/v0/...`,
   `/internal/...`) se enumeran versiones y endpoints olvidados. Es reconocimiento de
   inventario.
5. Enciende la corrección (`VULN_A4=off`) y repite el paso 1: ahora **404**. Esa es la
   calibración del arnés (`exploits/test_a4.py`): explotado en `on`, bloqueado en `off`.
